# Open Decisions and Assumptions

Status key: **Needs owner** = blocks a later phase until decided. **Assumed** = a working choice
we proceed with, which the owner can change.

## 2. Assumptions we are proceeding with

| #   | Assumption                                                                                                                                                                                                                                  | Why                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | Self-managed server-side sessions with Argon2id, rather than a hosted identity provider                                                                                                                                                     | The stack is MongoDB + NestJS. It keeps patient identity data in our own India-region database and avoids per-user vendor cost. It uses vetted libraries (`argon2`, Node `crypto`) and no custom cryptography. Revisit if enterprise SSO is needed |
| A2  | TOTP (authenticator app) is the first MFA method (implemented). WebAuthn/passkeys follow                                                                                                                                                    | TOTP is widely supported and works offline                                                                                                                                                                                                         |
| A3  | Patients register with email + password first. Phone OTP login comes when the SMS provider (D5) is chosen                                                                                                                                   | Avoids blocking on DLT registration                                                                                                                                                                                                                |
| A4  | The backend uses NestJS-native `class-validator` DTOs. The frontend uses Zod                                                                                                                                                                | Native Swagger and ValidationPipe integration on the server, Zod with React Hook Form on the client. The server is always authoritative                                                                                                            |
| A5  | No shared TypeScript package between web and api yet                                                                                                                                                                                        | Avoids build complexity for a beginner-maintained repo. The contract is OpenAPI. Generated client types can be added later                                                                                                                         |
| A6  | No Redis, queues, Docker or CI/CD initially                                                                                                                                                                                                 | Per the brief. Expiry and reassignment use database-driven polling inside the API until a measured need appears                                                                                                                                    |
| A7  | Atlas cluster in **Mumbai (ap-south-1)**                                                                                                                                                                                                    | Data residency and latency for Indian users                                                                                                                                                                                                        |
| A8  | Lint with **oxlint**, format with **Prettier**                                                                                                                                                                                              | Both official starter templates (NestJS 12, Vite 8) now ship oxlint, and it is fast and simple                                                                                                                                                     |
| A9  | TypeScript pinned to **6.0.x**                                                                                                                                                                                                              | TypeScript 7 is released, but NestJS CLI, typescript-eslint and ts-jest support only up to 6.x today                                                                                                                                               |
| A10 | Emergency guidance shows India's national emergency number **112**                                                                                                                                                                          | 112 is the nationally integrated emergency number (ERSS). State-specific numbers (for example 108) wait for clinical and operational review (D11)                                                                                                  |
| A11 | Synthetic seed data uses the reserved `.test` email domain                                                                                                                                                                                  | It can never reach a real inbox                                                                                                                                                                                                                    |
| A12 | One sign-in page for every role. Doctors register as normal accounts, then apply for doctor access                                                                                                                                          | The browser never picks a role. A reviewer grants it after checking the official register, which keeps unverified doctors out                                                                                                                      |
| A13 | Medical council, qualification and specialty are free text in doctor applications                                                                                                                                                           | The catalogue of councils and specialties arrives in Phase 2. Reviewers compare against the register by hand                                                                                                                                       |
| A14 | Appointment times use India Standard Time (UTC+05:30) for every doctor; timetable blocks cannot cross midnight                                                                                                                              | India has one time zone with no daylight saving. Overnight hours can be entered as two blocks (for example 22:00–23:55 and 00:00–06:00 next day)                                                                                                   |
| A15 | Unpaid bookings hold the slot for 10 minutes; patients may hold at most 2 unpaid bookings; slots need 30 minutes' notice and open 30 days ahead                                                                                             | Stops slot hoarding while leaving enough time to pay with UPI or cards. Values live in `booking-rules.ts`                                                                                                                                          |
| A16 | One fee per doctor for all consultation types, taken from the profile at booking time                                                                                                                                                       | Matches the current profile form. Separate fees per mode can be added later                                                                                                                                                                        |
| A17 | Online (video) slots are hidden and refused while no video provider is configured                                                                                                                                                           | Never take payment for a service that cannot be delivered                                                                                                                                                                                          |
| A18 | A payment that arrives after its slot went to another patient is refunded in full automatically; if nobody else took the slot, the late payment still confirms the booking                                                                  | Never double-book and never keep money for a booking that did not happen                                                                                                                                                                           |
| A19 | The patient's "reason for visit" is visible to that doctor only, and is not included in emails or audit logs                                                                                                                                | It is health information; email is not a confidential channel                                                                                                                                                                                      |
| A20 | Self-service account deletion removes the account, sign-ins, doctor application, profile and timetable. Past appointments, payment records and audit events are kept. It is refused while appointments are upcoming, and for the last admin | Medical and financial records may have to be kept by law (D12 legal review still decides periods and whether to anonymise further). Making people cancel first means refunds go through the normal path. The last-admin rule stops a lockout       |
| A21 | A video call can be joined from 5 minutes before the start until the end time; a call in progress is not cut off at the end time                                                                                                            | Chosen by the owner. Early joining lets people check their camera; not cutting calls mid-sentence is kinder than a hard stop                                                                                                                       |
| A22 | The video provider gets only an opaque room name, the labels `patient`/`doctor`, the doctor's public name and the word "Patient". Calls are not recorded and there is no in-call chat                                                       | Data minimisation: the patient's identity and health details stay on our servers. Chat and recording would need their own retention and consent rules                                                                                              |
| A23 | Patients may reschedule a confirmed appointment any time before it starts to another offered slot with the same doctor and consultation type; payment is unchanged                                                                          | Same window as cancellation (D9); avoids refund-and-rebook friction                                                                                                                                                                                |
